# Архитектура приложения «Тренировки»

Обновлено: 10.11.2026 · версия 19. Описывает код в `app/` (в репозитории GitHub те же файлы лежат в корне). Требования — в `fitness-pwa-spec-v1.1.md` (ТЗ, местами устарело, см. BACKLOG #17).

## Общая схема

```
тап по кнопке [data-a="действие" data-v="значение"]
        │
        ▼
app.js: обработчик click на #app  →  A[действие](значение)
        │
        ├─ меняет общее состояние S (state.js)
        ├─ сохраняет изменённое в IndexedDB (db.js)
        └─ render()  →  #app.innerHTML = экран + оверлей  (весь экран перерисовывается)
```

Роутера и фреймворка нет. Экран — строка `S.screen`, всплывающее окно — объект `S.overlay`. Каждый экран — функция, которая читает `S` и возвращает HTML-строку.

При запуске `init()` в `app.js`: `load()` читает всё из IndexedDB в `S` → разбирает `?go=` из адреса (ярлыки на иконке) → `render()` → регистрирует сервис-воркер (кроме localhost).

## Данные

### Хранилища IndexedDB (`db.js`)

| Хранилище | Ключ | Что лежит | В копии данных |
| --- | --- | --- | --- |
| `sessions` | `id` | Тренировки, включая идущую (`status: 'in_progress'`) | да |
| `measurements` | `id` | Вес (`weightKg`) и замеры объёмов (`waistCm`, `chestCm`, `bellyNavelCm`, `hipsCm`, `thighCm`). Вес и замеры теперь отдельные записи; в старых записях они могут лежать вместе | да |
| `activities` | `id` | Ходьба, домашние тренировки, групповые занятия, бассейн (`kind: 'pool'`), видео | да |
| `symptoms` | `id` | Записи о симптомах при стоп-сигнале: `{ at, kind, sessionId, stopSignalPressed, note }` | да |
| `kv` | `key` | Настройки и словари (см. ниже) | да |
| `photos` | `id` | Свои фото тренажёров (Blob) | нет (BACKLOG #11) |

### Ключи в `kv`

| Ключ | Поле в `S` | Что |
| --- | --- | --- |
| `settings` | `S.settings` | Дата старта цикла, сдвиги `shifts`, голос, имя, цель по весу, `lastBackupAt`, `lastBackupName`, `lastBackupHow` (`share` или `download`) |
| `plan` | `S.plan` | `{ days: { 'ГГГГ-ММ-ДД': переопределение дня } }` — тип дня, программа, отмена, вид визита в клуб |
| `health` | `S.health` | `дата → { steps, km, source }`; `source`: `manual` (вручную, имеет приоритет) или из Здоровья |
| `videos` | `S.videos` | Библиотека видео-тренировок со ссылками |
| `ex:<id упражнения>` | `S.exSettings[id]` | Настройки упражнения (единицы: кг или плиты) |

### Тренировка (`sessions`)

Создаётся в `startSession()` (`app.js`) и сохраняется после каждого изменения через `saveRun()`. Основные поля:
`id, date, slot` (программа: `A`, `B`, `cardio`, `pool` или id микса)`, week, phase, status` (`in_progress` → `done` / `partial` / `skip`)`, stage` (текущий этап экрана тренировки)`, sets[], wellbeing, lightDay, order` (порядок упражнений)`, rest, timer, checkInAt, finishedAt`. День клуба, отмеченный задним числом, — `retro: true` (считается как 2,5 ч, бассейн в нём — 45 мин).

Идущая тренировка живёт в `S.run`, завершённые — в `S.sessions`. Незавершённая старше 12 часов при запуске закрывается как «Частично».

## Экраны и переходы

- **Главная** (`renderHome`): шапка → Путь к цели → три плашки-кнопки → «Сегодня» → неделя → карточка «Копия данных» (внизу). Плашки: визиты (`goal-go visits`), вес (`weight-hub` — окно с быстрой записью и графиком), ходьба (`goal-go walk`).
- **Цели** (`renderGoals`): цели → кнопки → **Календарь занятий** (`#g-visits`) → визиты по неделям → **Вес** (`#g-weight`) → **Ходьба** (`#g-walk`) → талия → замеры. К блоку можно перейти действием `goal-go`: оно кладёт `S.focus = 'g-…'`, а `go()` после отрисовки прокручивает к элементу с этим id.
- **План**: неделя и месяц; месяц рисуется тем же `calGrid`, что и календарь в «Целях» (цвет — минуты за день, подпись — часы, точка — был в клубе).
- **Карточка дня** и блок «Сегодня» собираются одной функцией `dayItemsHtml(date)`. В ней: основная активность дня (зал, либо дома — «Видео или йога» и Ring Fit; отдельной «Прогулки» нет, её заменила «Ходьба за день»), **«Ходьба за день»** (шаги из `S.health` или по прогулкам, прогресс к плану, кнопка «Изменить»), выбранное групповое занятие, строка «Бассейн» (отметка или свободные окна), список групповых занятий.
- **Оверлеи** (`S.overlay.type`): `day`, `move`, `cancel`, `video`, `act`, `steps` (шаги и км), `weight` (старый вариант), `weightHub`, `backupDone`, `stop`, `pressure` и др.

## Ключевые потоки

**Какая программа сегодня.** `plan.slotFor(date, plan, startDate, { today, sessions })`: дни клуба по умолчанию Вт/Чт/Вс (`DEFAULT_GYM_WEEKDAYS`), переопределения из `S.plan.days`. Очередь недели А → кардио → Б раздаётся по сделанному, а не по позиции дня. Старая версия `cycle.plannedSlot` ещё в коде — не использовать (BACKLOG #18).

**Неделя и фаза.** `cycle.weekOf(date, start, shifts)` → `cycle.trainingPhase(week)` → `PHASES` (повторы, отдых, кардио, шаги). Неделя 0 — вводная, 1–4 Освоение, 5–8 Набор, 9–12 Закрепление, 13 разгрузка. Неделя в приложении — с понедельника по воскресенье.

**Рабочий вес.** `suggestionFor(ex)` в `app.js` собирает историю подходов из `S.sessions`, оставляет только подходы в текущей единице (`progression.splitByUnit`) → `progression.suggest()`.

**Плитки и кг.** Это разные шкалы, масса плитки неизвестна, поэтому пересчитать их нельзя. Каждый подход хранит свою единицу (`unit`; у старых подходов без неё считается единица упражнения по умолчанию). При смене единицы подсказка строится только по подходам в новой единице; если их нет — «Подбери вес», а прошлые подходы показываются с подписью («3 плит.×15»). Идея пересчёта по массе плитки — в BACKLOG.

**Шаги и километры.** Одна мерка: `STEPS_PER_KM = 1350` (`stats.js`), `stepsToKm` / `kmToSteps`. Правим одно поле — второе пересчитывается. Где что хранится:
- за день целиком — `S.health[date]` (`steps`, `km`, `source`). Приоритет: ручной ввод → Здоровье → оценка по отмеченным прогулкам (`estSteps`/`estKm`). Загрузка из Здоровья не перезаписывает ручные дни;
- отдельная прогулка — запись в `activities` с `distanceKm` и `steps`;
- на домашнем дне шаги за день, введённые вручную, создают запись прогулки с `fromDaySteps: true`, чтобы день считался отмеченным.
План шагов в день — `plan.stepsGoalOn(date)`: по фазе недели (7,5 / 8,5 / 9,5 тыс., разгрузка 7 тыс.).

**Шаги из Здоровья.** «Команда» iPhone копирует шаги в буфер → «Вставить из буфера» (блок «Ходьба» в «Целях») → `stats.parseHealth(text)` → `S.health` → `kv.health`. Инструкция по созданию Команды лежит там же, в блоке «Ходьба».

**Бассейн.** Считается из трёх источников: таймер в тренировке (`session.pool`), аквааэробика (`session.aqua`), отдельная отметка `activities.kind = 'pool'`, а также день клуба, отмеченный задним числом (45 мин). Всё это собирает `stats.swimMinutesOn(date)`. Свободные окна бассейна по дням недели — в `plan.POOL_FREE`. Бассейн и групповое занятие считаются визитом в клуб (`clubVisitDates`).

**Визиты.** `clubVisitDates()` — дни с выполненной тренировкой (`done`/`partial`), групповым занятием или бассейном. `visitCounts(today)` даёт «за месяц» и «всего с даты».

**Таймеры.** Хранятся как метки времени в `S.run.rest` / `S.run.timer`, а не как счётчик, поэтому переживают сворачивание и перезапуск. `tick()` раз в секунду обновляет только цифры в DOM, без полного `render()`.

**Копия данных.** `doExport()` → `db.exportAll()` → JSON-файл через окно «Поделиться» (на iPhone) или обычное скачивание. После успеха сохраняются `lastBackupAt`, `lastBackupName`, `lastBackupHow` и показывается окно «Копия сохранена» с именем файла. Приложение не может узнать, какую папку выбрала пользователь, поэтому показывает имя файла и подсказку, где искать. `stats.backupStatus()` определяет напоминание: больше 14 дней — «давно», больше 30 — «очень давно», копий не было при ≥3 записях — «нет копии»; карточка внизу главной подсвечивается. `doImport()` → `db.replaceAll()` полностью заменяет хранилища (кнопка в «Настройках»).

**Обновление на телефоне.** `sw.js` отдаёт файлы из кэша сразу, свежие тянет в фоне — новая версия видна со следующего запуска. Смена `VERSION` в `sw.js` создаёт новый кэш и удаляет старые.

## Куда класть новое

- Новый экран вне тренировки → функция `renderX()` в `views.js` + строка в `screens` внутри `renderMain()` в `app.js`.
- Новый этап тренировки → `renderX()` в `app.js` + значение `S.run.stage`.
- Новое действие → ключ в объекте `A` в `app.js`, кнопка с `data-a`.
- Новое постоянное значение → ключ в `kv` (загрузить в `load()`, сохранять отдельной `saveX()`), новый тип записей → новое хранилище в `db.js`.
- Новое содержимое (упражнения, программы) → `data.js` / `programs.js`, без логики.

## Курс на универсальный продукт

Приложение делается для одного человека, но задумано как основа для фитнес-приложения для людей с ограничениями (зрение, шея, лишний вес, колени, спина) — тем, кто хочет результата, но не может тренироваться «как все». Поэтому при любых изменениях:

1. **Личное — в настройках, не в коде.** Всё, что относится к конкретному человеку, должно жить в данных (профиль, настройки, содержимое), а не в логике. Новые числа и расписания не зашивать в функции, а выносить в именованные константы в одном месте.
2. **Ограничения — отдельное понятие.** Стоп-сигналы, запрещённые и осторожные упражнения, замены — данные, привязанные к ограничению, а не к человеку. Новый человек выбирает свои ограничения, а не получает чужие.
3. **Содержимое отделено от логики.** Упражнения, программы, групповые занятия — в `data.js` / `programs.js`; логика (`cycle`, `plan`, `progression`, `stats`) о них ничего не знает.
4. **Данные принадлежат пользователю.** Хранение только на устройстве, копия данных — штатная функция. Любой переход на облако или аккаунты — только осознанным решением.
